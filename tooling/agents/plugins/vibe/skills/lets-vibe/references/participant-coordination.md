# Participant coordination

Use this reference for an assessment selected under [Lets Vibe's defaults or user steering](../SKILL.md#independent-assessments), or other explicitly authorized delegation. Do not add helpers beyond that selection. Apply repository instructions on primary-agent ownership when preparing the assignment and returning its result.

## Continuity and authority

Keep one stable participant task per semantic role within the agreed run. Follow up with the same participant after corrections, retry, changed instructions or a revised candidate; distinguish attempts by the reviewed candidate and result, not task-name suffixes. If continuation is unavailable, explicitly identify the replacement and provide the current assignment and prior findings. Do not silently transfer sign-off or represent the replacement as the original reviewer.

A persistent read-only reviewer may inspect a candidate at a material checkpoint when authorized. Use an advisor for a concrete unresolved conflict in evidence; do not add overlapping roles for ceremony. A Review Vibe or Test Vibe invocation in the implementation task, whether directly requested or composed by an authorized workflow, authorizes one independent assessor for that assignment. An already independent assessor performs the work directly. Selecting other supporting methods does not authorize additional agents or delegated approval. Independent sign-off must come from the assigned independent participant. The distinction between assessment and authorization follows [contract core](contract-core.md#steering-and-checkpoints).

## Assignment

For each actual participant, provide:

- The objective, agreed scope, exclusions and completion boundary.
- The exact checkout and candidate: relevant commit identity, included uncommitted changes and any working-tree constraints.
- The exact document or task-record paths selected under [slice-document reuse](requirements-alignment.md#reuse-the-slice-documents), relevant accepted decisions and applicable instruction paths. Include specific excerpts or snapshots where necessary to avoid ambiguity; do not paste unrelated policies or full transcripts.
- Concrete success criteria, expected verification and evidence already available, including limitations and previously confirmed findings.
- The allowed write scope, active execution mode, user checkpoints and expected result location or response format.

Require a clear outcome: PASS when the assigned criteria are met, FIX with supported findings when correction is needed, or ESCALATE with the exact unresolved question or authority boundary. Passing the participant's assignment does not imply the entire slice is complete.

Each participant reads the complete applicable root and nested instructions before acting, root to leaf. Inherited context is not a substitute for that read. After context loss or changed guidance, recover the current assignment, applicable instructions, decisions and unfinished work before continuing. Nested delegation inherits the same obligations and requires authorization.

A top-level task setup is not an independent-review assignment. Keep setup focused on the requested work, current steering, mode, checkpoints and terminal stop; reserve candidate-specific review material for the actual review handoff.

## Corrections and return

For a follow-up requested by the user or included in the accepted assessment scope, give the same assessor the updated candidate, changes addressing each finding and current verification. Corrections alone do not authorize another assessment. Keep prior findings visible until resolved, shown inapplicable or explicitly accepted as limitations. Confirm that the returned result applies to the current candidate; changed implementation may require reassessing affected evidence.

Stop the assignment when its completion criterion is met. Report scope discoveries without expanding the assignment. Return bounded findings and evidence to the primary agent, which verifies them before acting and presents the actual review disposition to the user.
